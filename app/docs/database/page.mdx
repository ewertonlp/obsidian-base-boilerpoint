
# Database & Supabase

Your boilerplate is pre-configured with a robust Postgres database via Supabase. We also include a ready-to-use schema for your SaaS.

## 1. Running Migrations

When you create a new Supabase project, you need to set up your tables. We provide a SQL script that creates the `users` and `subscriptions` tables automatically.

Go to your Supabase Dashboard, open the **SQL Editor**, and paste the contents of `supabase/schema.sql` (found in the root of this project).

## 2. Row Level Security (RLS)

Security is built-in. By default, Row Level Security is enabled on your tables. This means users can only see and modify their own data.

Here is an example of the policy already applied to your `subscriptions` table:

```sql
CREATE POLICY "Users can view own subscription" 
ON subscriptions FOR SELECT 
USING (auth.uid() = user_id);
```

## 3. Bypassing RLS (Admin Tasks)

Sometimes your server needs to update a table regardless of who is logged in (for example, when Stripe sends a Webhook event). For these specific cases, use the supabaseAdmin client which uses the Service Role Key:

```typescript
const { data, error } = await supabaseAdmin
  .from("subscriptions")
  .update({ status: "active" })
  .eq("user_id", userId);
```
